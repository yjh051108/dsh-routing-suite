# dsh-graded-mode 设计理念（三段话）

> 依据：README.md、docs/design-v4-edit-lock.md 与 src/ 源码整理；成稿于分级流程（3 大类 / 9 小类）。

**一、定位与承诺。** dsh-graded-mode 是会话级、命令一次性触发的任务协议插件：只有用户显式输入 `/graded <任务>` 才会启动分级流程，未触发时对官方环境零痕迹——不注册任何工具、不注入任何提示、不做任何字符串解析，一切保持官方原样。分级因此不是环境常驻规则，而是一次"用户拍板"的人机协议：大任务拆成哪几块、分化到什么粒度，由用户显式启动并逐步确认（大类锁定 → 小类锁定 → 审核），模型只负责提案与执行，不再自发决定任务结构。

**二、机制与语义。** 流程完全由工具驱动：`edit_plan` 与 `lock_stage` 两个语义化工具按 level 参数切语义，阶段推进 = 工具调用事件（lock 成功即切阶段），协议语言内建于工具 API，全程零字符串解析、零内容识别，插件从不"猜测"模型意图。顺序强制且"锁了就是锁了"：先大类、锁定，再小类、锁定，已锁层再编辑会被工具直接拒绝，解锁的唯一入口是用户审核拒绝——把"人最终掌舵"从自觉变成机制。L1+L2 全锁后所有门自动关闭，插件直接弹原生树状图审核（`ctx.userQuestions.ask`，不经过模型转述），确认与否由用户真实回答驱动；清单只存在于结构化树与 `graded/plan`、`graded/lock` 事件快照，全程不写官方 todo_write——官方任务面板零污染，GUI 树状图由 client 插件同源渲染。

**三、边界与红线。** 三条红线守住边界：一是零侵入——不碰官方源码（dsh-tool-todo 一行不改、content 协议零侵入）、不新增"确认"工具（复用原生 userQuestions）、工具只在会话 agent 层注册，不污染全局工具面；二是不常驻——每个阶段只注入一次引导、开发期每小类只注入一次焦点提示，未激活 = 零工具、零注入、零改变，没有监督面板也没有后台循环，任务粒度由工具 API 当场把关而非常驻盯梢；三是粒度可验——每个小类都是"能一截图/一运行独立验证"的完成单元，核心概念 ≤3 个（超限提示拆类而不改名），执行期单线聚焦、完成一个标定一个、不一把梭——用可验证的小步换大任务的确定性与交付质量。
